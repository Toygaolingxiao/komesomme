## 1. 一言で

KomeSomme は「米のデータベースサイト」でも、「LLM と雑談して米を薦めるサービス」でもない。触れる和紙の味わい地図である。手で位置を選び、口で米ソムリエに相談し、購入は検索型のリンクで店へ渡す。ベクトル検索と短い返事は裏側に置く。

## 3. コンサルの視点

### 3.1 なぜ機会があるか

日本のブランド米は比較コストが高い。店頭は名前と産地、食味図はサイトごとに軸が違い、ふるさと納税と EC はまた別の検索語である。KomeSomme は「今夜何を食べるか」を、地図の一手と相談の一言に畳む。在庫は持たず、キーワードを持って店へ出す。これは「より詳しい米 wiki」とは別の勝負である。

最初から収益の切り口は決まっていた。楽天 / Yahoo / Amazon / ふるさとの **検索 CTA + アフィタグ** であり、商品 API を先に作ることではない。API は P2。1.0 前に繋ぐべきなのはタグである。

### 3.2 意図してやらなかったこと

- 栄養計でも公定の食味計でもない。スコアは編集評価である。UI とプライバシー文もここを守る。一度「測った値だ」と誤解されると信頼が壊れる。
- 万能 AI にしない。順位は LLM に渡さない。LLM は Top 4 が決まったあと 2 文だけ書き、名簿に無い銘柄名を作らない。
- キャラクター IP にしない。侍・刀・マスコットは使わない。探針と米粒が記号で、米ソムリエは職能名である。
- 販促に 最強 / 圧倒的 / 究極 / 唯一無二 / 爆発 / 神 / 無敵 を使わない。「神奈川」が「神」に誤反応したことがある。禁則は部分一致だけでは足りず、許可リストが要る。

### 3.3 事業と法令でまだ裸の部分

友人に見せられる体験にはなっている。**アフィ付きの正式サイトとしては、まだ金と紙が足りない。**

- 特商法の事業者欄はプレースホルダ（日本で公開販売するときの硬い門）
- アフィタグ未接続。クリックは店に着くが、成果が帳簿に戻らない
- GTM ID 未設定。GA4 に初週の CVR が無い
- Sentry が無い。相談の 502 は Vercel のログを開くしかない

コンサルとしての提案: 1.0.0 は Auth、お気に入り、炊飯アドバイスを待たない。待つのは **特商法の記入 + アフィチャネルが少なくとも 1 本で突合できること + スモーク試験の記録**。観測はまず `access_events` で足りる。GTM は加点であり、公開の門ではない。

### 3.4 いま言えるプロダクトリスク

| リスク | 意味 |
| --- | --- |
| スコアの論争 | 外部図の軸は 甘み×粒立ち と一致しない。再校正は「図の合意 × 公開資料 × 旧値、衝突は保守側」としたが、別の図を持った利用者は詰め寄れる。対策は透明性。編集分であることと軸の定義を画面に出す。 |
| 相談の幻覚 | Flavor Bridge と短い返事の制約で押さえている。賢く見せるために catalog 全体を prompt に載せない。 |
| コスト | 地図は無料。相談は回ごとに embedding と任意の LLM。レート制限と kill switch は残す。 |
| カタログの欠落 | 図にあって catalog に無い銘柄（秋の詩 など）は意図的に足していない。品揃えが薄いと「専門家」感が傷つく。追加は derive / validate / seed の同じ経路。Table Editor に手で行を足さない。 |

## 4. 開発者の視点

### 4.1 当たっていた設計

**二系統の推薦**が、このサイトでいちばん高い判断だった。座標操作はクライアント、相談だけ Gemini / pgvector。体感が速く、請求が読め、障害時も地図は生きる。

**打分は Git、検索は DB。** `validate:rice` が seed の前に重複 ID、禁則、必須配列を止める。味わいを直すのは `sources/`（または `scripts/data/` の正本を apply）であり、Table Editor の数字を回すことではない。

**RAG は検索 + ルールの説明まで。** Corpus は自然な日本語の `search_text` で、JSON のキー名ではない。Index は pgvector。Generator は極端に軽い。「チャットボットに米を被せたもの」より測りやすく、戻しやすい。

**匿名面は小さく。** 0004 以降、embedding / RPC は anon から見えない。`access_events` の INSERT は service role のみ。ブラウザが取るのは catalog の行だけ。

### 4.2 踏んだ穴

- **社内ネット:** Gemini / Supabase の `fetch failed` が灌庫の先頭で連続することがある。embedding の再試行だけでは足りず、upsert も再試行する。企業 CA は `--use-system-ca`。
- **軸の写像:** 外部図は もちもち / あっさり など。こちらの軸は改名せず、写すだけ。軸を変えるのは製品の記憶を変えることなので、主理人の明示が要る。
- **文書の「現在のバージョン」:** overview、checklist、changelog の文頭、docs 索引に書いていた。1 箇所忘れると文書が嘘をつく。正本はいま `VERSION` + `package.json`。
- **空のモジュール:** 未接続の `RakutenAffiliateClient`、未使用の `createServerClient`、コードが読まないアフィ env は、「もう繋がっている」ように見える。コードが読まない変数は `.env.example` に置かない。
- **秘密情報:** `.env.local` を整理させると、エージェントが service_role を読む。以降は `.env.example` だけ直し、ローカルファイルは人が合わせる。

### 4.3 エージェントと組むときに効いた約束

Cursor の rule / 文書に書き、何度も実行したもの:

- 推薦式と座標式は、明示が無い限り変えない
- mock しない。本番へ勝手に seed しない
- UI は日本語。GAO への説明は中国語
- 番号を上げるのは、利用者が感知する `main` の変更と同じ commit。1.0.0 を機能 commit に混ぜない

これが無いと、エージェントは「ついでに」打分や口調を変え、commit ごとに bump し、`NEXT_PUBLIC_` に service_role を入れる。

## 5. まだ机の上にある課題

「アフィを公開して受け取れる」を止める順:

1. 特商法の記入
2. アフィチャネルが少なくとも 1 本、タグ + 突合方法
3. [smoke-test.md](./smoke-test.md) に沿った記録
4. `NEXT_PUBLIC_GTM_ID`（任意だが安い）
5. Sentry（相談の失敗率）
6. 独自ドメイン

この前に Auth、お気に入り、炊飯アドバイス、商品検索 API を広げない。それは別の製品曲線である。

## 6. 収穫（次のプロジェクトへ持っていくもの）

1. **先に「絶対に変えないもの」を決める。** ここでは式、軸、案内役の名。残りは反復してよい。
2. **利用者の手ぶりと課金動作を分ける。** 地図をドラッグしても無料。相談を送ったときだけモデルを呼ぶ。
3. **正本は少ないほどよい。** バージョンは 2 箇所、env はテンプレ 1 枚、打分は sources 一式。「現在の状態」の 3 枚目は必ず腐る。
4. **編集データは監査できる形にする。** 再校正は extract / overrides / reason を残す。「動かした覚えがある」より役に立つ。
5. **公開チェックは Done 条件で書く。願望で書かない。** `11` の P0/P1 は「将来要件」一覧より実行できる。[06-requirements.md](./06-requirements.md) の将来節は `11` を指すように直した。
6. **エージェントは加速装置であり、鍵の保管庫ではない。** テンプレは任せてよい。`.env.local` は開かせない。
