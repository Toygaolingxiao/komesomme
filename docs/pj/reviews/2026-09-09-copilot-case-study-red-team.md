## 综合定级

高级 Demo / 工程交付型作品集。技术实验的完整度高于商业证据，尚未成为可规模化复制的产品案例。

## 核心漏洞与硬伤

1. 报告证明了“能做出来”，但还没有证明实验结论成立。二维味觉坐标、Top 4、语义检索和人工标签都缺少离线评估集与用户反馈闭环。
2. Git 目录是可维护的数据资产雏形，不是现成护城河。标注依据、一致性、更新工时、回滚和版本绑定需要被明确。
3. 技术选型方向合理，但 trade-off 仍以判断句为主，缺少延迟、成本、并发、故障恢复和迁移触发线。
4. Git 正本、数据库副本、embedding 版本之间的发布一致性没有讲透。seed 中断、模型切换和回滚路径应成为交付证据。
5. 商业入口存在，但不应成为当前案例的主证明。`shop_click`、SKU 对齐和 affiliate 收益可作为后续观测面，而不是当前价值结论。
6. 安全章节识别了限流绕过、prompt injection、成本暴走和 CDN 完整性问题，但部分控制仍停留在下一阶段计划。
7. 交互层很有表现力，但键盘 slider、移动端横向滚动、错误状态和关键动画失败后的可见性仍需补强。
8. 旧文案过度防御，反复强调“不是投资人资料”和“价值未验证”，削弱了技术实验本身的主线。

## 红队质问

1. 如果把米换成另一类商品，哪些部分仍然成立？不可替代性来自领域数据、推荐评估，还是视觉体验？
2. 你如何证明二维距离与用户感知相近，而不是作者自己定义的坐标游戏？
3. 当目录标签错误时，谁发现、谁修正、如何回滚？Git 提交记录本身不是质量闭环。

## 高价值改进清单

- 将主叙事改为“实验问题 → 架构决策 → 可观测证据 → 交付边界”。
- 为推荐建立固定评估集，记录 Recall@4、NDCG、覆盖率、多样性或至少专家一致性。
- 为 catalog、embedding、规则和部署建立同一发布版本，并展示失败与回滚路径。
- 增加压测、模型超时、数据库不可用、seed 中断等故障实验记录。
- 把商业化放入“后续观测”章节，保留事件设计，但不把未发生的点击或收入写成成果。
- 保留矩阵、泳道和 roadmap，强化它们的叙事作用，减少纯文字说明。

## 吸收说明

本轮重构采用“技术实验优先”的前提。商业化不删除，但从首页结论降为后续观测面。页面文字、章节顺序和视觉系统同步调整，详见当前 Case Study HTML。
