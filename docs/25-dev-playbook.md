# 开发方案与复盘（2026-11）

写给 GAO。这篇讲两件事：这几个月我们怎么走偏的，以及以后怎么开工才不会再绕回去打磨首页。

接下来做什么，只看 [20-growth-plan.md](./20-growth-plan.md) 的第 4.0 节。谁开哪条分支，看 [24-collaboration.md](./24-collaboration.md)。Cursor、Muse 和其他助手都要守 [`.cursor/rules/dev-playbook.mdc`](../.cursor/rules/dev-playbook.mdc)。本文不再另写一份产品路线。

---

## 1. 2026-11 复盘

站已经过了 1.0。从 9 月到 11 月，版本走到 **1.9.2**。地图、咨询、事典、料理页、特集、分享卡、关于页，这些都有了。缺的不是再把某一屏修好看一点，而是比较页还没有，后台也看不出人是从哪一类页面走进店的。

### 1.1 履历（按能力，不按每个 commit）

| 时段 | 留下的形状 | 现在怎么看 |
| --- | --- | --- |
| 构想 → 数据 | 手写 `RiceSource` → catalog → seed。分数在 Git | 选对了。在表格里拧数字会毁审计 |
| 双轨推荐 | 地图在浏览器里算距离；咨询才调用模型 | 整站最值钱的决定。继续守 |
| UX 1–6 → 1.0 | 购买出口、法务、限流、CI、`komesomme.jp` | 上线清单按做完的条件写，所以能上线 |
| Phase 1（1.1） | 给搜索引擎看的结构化数据和分享图 | 检索地基够用，不必再扩一套 SEO 架子 |
| Wave 2A（1.2） | 十个料理页，带比较表 | 曝光的主入口已经有了。后面只补人手写的开头，不新开框架 |
| 1.4 事典 | 合稿和溯源 | 案例可以讲。分数仍是编辑评价 |
| 1.5–1.6 | 动效、版心、县检索、图框 | 用户看得见，但开始进入打磨螺旋 |
| 1.7–1.8 | 分享卡默认开、大图、十月特集、新米和锅的更新 | 分享能力提前做了；季节页在走 |
| 1.9 | 不再随页下发一堆字体、加上关于页、首页变瘦、咨询设了预算 | 页面更快了。比较页仍没有 |
| 2026-11 治理 | 写下协作规则、拆开 CI、关掉过期工单 | 规则写了，执行还不稳定 |

### 1.2 选对了

拖地图不花钱，按咨询才调用模型。推荐公式、坐标轴、侍米師这个名字，一开始就钉死了。版本号只留两处，打分只留一套源文件，环境变量只留一份例子。1.0 用上线清单，不用愿望清单。对外网站只讲今晚吃什么，不讲作品集和时薪。咨询不是聊天机器人：县名出现在问句里，就只出该县的米。

### 1.3 走偏了

1.0 之后小版本发得太密。八周里从 1.4 走到 1.9，大量是版心、图框、字体、特集微调。比较页、购买直链、按页面种类看漏斗，几乎没动。

分享卡已经默认打开，比较页还没有。让人再来的能力，跑到了「先比清楚」前面。

几个助手同时改同一份更新日志和版本号，合的时候还是要人收拾。

「推到主干」和「一人一条分支」两套说法并排，助手会各执一词。日常走分支和审查。只有你说推送，并且改动已经在本地主干上，才往远程推。

图先做成字砖，再裁成扁长条把饭碗切掉，才退回能看清的侧图。画幅用原来的比例，不要发明新的。

观测工单挂了两个月。代码完成后，每周看半小时数据就够，不要为 GA4、Sentry、Search Console 再开一张票。

冲突的旧修补拖着，最后整枝废掉，补丁也没上主干。要留就从最新主干重开，不留就马上关。合完的远程分支记得删。

### 1.4 以后照着做

一周只改一条能看见结果的产品线，同时改两处就说不清是哪处起了作用。一件用户能感觉到的事，就一个审查。用户能感觉到才升版本号，只改文档或规则不要升。动手前先看有没有别人还没合的改动会碰到版本号或更新日志。用浏览器把路径点一遍，不要只看一张截图。不改公式，不编分数，不用特 A 的次数当购买理由。日文要像店头荐米。

| 试验怎么写 | [test-specification.md](./test-specification.md) |

大改先用中文说明怎么切，你点头再开分支。一个人写，另一个人看。不新装流程工具，也不新加月费。

### 2.2 动手之前先回答

1. 这是比较页、季节特集更新、再访功能，还是已经滑到桃、和牛、登录这些构想里了？
2. GitHub 上有没有别人还没合的改动，会碰到版本号、安装清单、更新日志或特集数据？
3. 会不会改推荐公式、坐标轴、侍米師这个名字？
4. 新日文能不能念给店头的人听？
5. 浏览器里要点开哪几条路径才算验过？

第一问答不上来，就不要开分支。

### 2.3 怎么切

用户能感觉到的一件事，就一条分支、一个审查。标题写清是谁做的。特集文案、持续集成、字体、分享卡预览，不要塞进同一个审查。主干上有没提交的改动，先挪到一边或另开分支，不要在主干上叠两件活。

### 2.4 一周怎么过

只挑成长计划 4.0 节里的下一件。改首页长相、把那段说明重新显示出来，都不算主题。本机先跑单元测试；动到画面就先构建再跑浏览器测试，并且自己把主路径和旁边的页点一遍。作者以外的人留一句结论。你说可以合才合，合完把远程分支删掉。每周留半小时看搜索数据和观测台，不要为此开工单。

### 2.5 做到什么算完

验收能测。相关路径自己点过，或者交给持续集成。检查项要绿：文案检查、类型、米数据校验、单元测试、构建、打包体积、浏览器测试。用户能感觉到的改动，和升版本号放在同一次提交。牵涉联盟、法务、权限，对照烟雾记录和上线清单。每次正式上线之后，在烟雾记录里写一笔。新的可被搜索收录的页，还要有标题、分享图、结构化数据、内部链接、联盟标记、站点地图和一条浏览器测试。

### 2.6 分支、主干、推送

日常从最新主干开自己的分支，开审查，你说合才合，合完删分支。

你说「推送」或「推到线上」，并且改动已经在本地主干上，才按推送规则推到远程。第一次被拦住是预期的，用同一条命令再走一次审批。

本地主干落后又有没提交的改动，先挪到一边再快进拉远程。挪出来的内容和远程重复，就丢掉。

冲突的旧审查，从最新主干重开，或者马上关掉。不要留着脏状态。

助手默认不直接往主干写。只有你明确说推送，并且工作区已经在主干上，才走推送。

### 2.7 这段时间不要做

不要做登录、收藏、多轮咨询、做成 App、自营库存。不要做桃、和牛、酒的新站。不要为了看数据再开工单。不要改推荐公式或坐标轴。不要用特 A 当购买理由。不要一次生成超过两张铭柄画。不要把县的图裁成扁长条。不要在本仓加项目管理工具。不要把首页给搜索引擎看的那段说明重新显示出来。

## 3. 开工时别走偏

具体做哪几页、做到什么算完，都写在 [成长计划第 4.0 节](./20-growth-plan.md)。这里只提醒四件容易又做错的事。

比较页先写 8 到 12 对就停，同时把观测台按页面种类拆开。不要一上来就铺 50 对。

首页下面那段「这个站是干什么的」是给搜索引擎看的，人滚不到。不要把它重新显示出来。

分享卡已经能用。比较页还没做成可观察之前，不要去做 LINE，也不要重做分享卡。

以前那条修首页详情卡的旧分支已经废了。如果线上点米仍然没有详情，从现在的主干重新开一个很小的修补。
