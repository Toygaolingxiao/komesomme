# KomeSomme UI デザイン仕様

この文書を KomeSomme の UI デザイン正本とする。旧 `1637_change.md` と `design_change.md` の有効な要件を統合し、今後の UI 実装・レビューは本書を基準にする。

## 1. 体験コンセプト

KomeSomme は、AI ダッシュボードではなく「和紙の味わい地図に触れ、炊きたての一膳を選ぶ」体験である。AI やベクトル検索は裏側に置き、画面では米、産地、料理との相性を主役にする。

- 印象: 明るい、鮮やか、食欲が立つ、上質
- モチーフ: 炊きたての米、果実、旬の食卓。灰がかったモランディ色は使わない
- UI の役割: 味の位置を直感的に選び、推薦の優先順位を迷わず読めること
- 動き: 短い fade、穏やかな spring、探針の淡い ripple。派手な bounce、回転、走査線は使わない

## 2. カラーと質感

基本色は次の4系統とし、白一色や純黒を避ける。灰がかった低彩度（いわゆるモランディ色）は使わない。

- **Rice white**: `#FFFDF7`。マップ面。濁さない
- **Paper**: `#F6EBDD`。ページ地
- **Cream**: `#FFF5E5`。推薦面、タグ
- **Ink**: `#302820`。本文
- **Muted**: `#766658`
- **Brown**: `#704522`
- **Gold**: `#D49A2A`
- **Harvest**: `#E56B3F`。CTA と選択点の強調。銘柄点の塗りには使わない

背景は穏やかな米色。彩りは点・タグ・バッジ・CTA に置く。neon、純黒、寒色の glassmorphism は使わない。Desktop は外枠 1 枚（マップ＋推薦）で画面をまとめ、No.1 だけ内側カードにする。

地域色は旬の食材のように色相を離す。画面は `src/lib/rice/regions.ts` を優先して塗る。

- 北海道・東北: `#3F8FA3`（水）
- 関東・甲信越: `#7CA83B`（若葉）
- 東海・北陸: `#E29A35`（実り）
- 近畿: `#C85A72`（梅）
- 中国・四国: `#4C9B72`（竹）
- 九州・沖縄: `#E56B3F`（柿）
- 全国銘柄: `#8C6BB1`（紫）

銘柄点は地域色の米粒オーバル。No.1 は収穫色の光輪とテイスティングラベル。象限の言葉は軸ラベルに任せ、描画面の中に置かない。

## 3. 味わいマップ

### 軸

軸の向きは左が淡く右が甘い、下がかたく上がやわらか。文言は他サイトの食味図と揃えない。

- X 軸: 左 **すっきり澄む** → 右 **甘みふくらむ**（データは `sweetness` 1〜5）
- Y 軸: 下 **粒立ちしっかり** → 上 **やわらか、ほどける**（データは `hardness`。1=やわらか、5=しっかり。表示 Y だけ反転）
- `stickiness`（粘り）は点サイズと詳細表示に使い、座標軸にはしない

四象限は軸の四隅で読む。描画面の中に象限コピーは置かない。

### 点と探針

- 銘柄点は **米粒オーバル**。形は id から決定論的に少し変える。位置は display 座標のまま
- No.1 はテイスティングラベル（県名＋銘柄＋短いタグ）と収穫色の光輪
- No.2〜4 は地域色のまま輪郭を少し強くする。ラベルは hover / focus
- その他は地域色、hover でラベル
- 凡例ホバーで該当地域以外を淡くする
- 小画面では点を間引く。キャンバス短辺が約 420px 未満なら推薦以外を淡く小さくし、約 300px 未満なら Top 4 と選択中だけを描く
- 配置は `calculateMatrixDisplayPoint` の後、決定論的な衝突回避（最小間隔約 0.15 軸単位）
- 探針は墨茶色の小点と淡い波紋。十字照準や HUD にしない

マップクリック、探針ドラッグ、スライダー操作は座標推薦だけを即時更新する。LLM や意味検索を起動しない。

マトリクスの描画面は、左ペインの残り領域で軸ラベルと凡例を除いた矩形いっぱいに広げる。銘柄点は枠のすぐ内側（inset 約 4%）まで置く。軸ラベルは描画面の外側の墨茶カプセル。産地凡例は下。Desktop は 100% 表示で一画面に収める。横軸は左すっきり澄む・右甘みふくらむ。縦軸は下粒立ちしっかり・上やわらか、ほどける。内部の `hardness` は 5=しっかりのまま、表示 Y だけ反転する。

相談が返ると探針は **1 位銘柄の表示座標**（jitter 後の点の上）へ移る。地図をドラッグするかスライダーを動かすと座標推薦に戻る。

## 4. 情報設計

### Desktop

```text
┌──────────────────────────────────────┬──────────────────────────┐
│ 味わいの地図                          │ 今日の一膳                 │
│ [ 味わいマップ（残り領域いっぱい） ]    │ No.1                     │
│ [ 現在の味わい ]                      │ 近い銘柄 No.2〜4         │
└──────────────────────────────────────┴──────────────────────────┘
│ 言葉でえらぶ、今日の一膳（通欄）                                 │
```

- 左: マップ、その直下に現在の味わい（粒感・甘み）
- 右: No.1 と近い銘柄 No.2〜4。米ソムリエの返事は置かない
- 相談は両欄の下に通欄。意味検索の返事は相談欄で例句スロットと入れ替える（欄の高さは変えない）。入力欄は残し、続けて聞けるようにする。「地図で選び直す」も相談欄に置く
- Desktop は `100dvh` に収め、ページ全体のスクロールを出さない
- 左右は同一の外枠に収める。右カラムにページ全体のスクロールを設けない。短い画面では右カード内だけが必要なら縦に動く
- 詳細ダイアログは内容量に応じて独立スクロールしてよい

### Mobile

1. ヘッダー
2. タイトルと説明
3. 味わいマップ
4. 現在の味わい（粒感、甘み）
5. No.1
6. No.2〜4
7. 米ソムリエに相談

## 5. 推薦表示

- **座標推薦**: クライアントで display 座標の距離を計算し、整数スコア（45〜100）の Top 4 を即時表示
- **意味検索**: 相談フォーム送信時だけ `POST /api/rice/semantic-recommend` を呼ぶ。サーバは相談文に食味の補助語を足してから embedding し、Top 4 を取ったあと Gemini が 2 文の返事を書く。銘柄名の創作はしない。返事は相談欄の例句スロットに出し、入力欄は残す。探針は 1 位の表示座標へ移し、マップの強調もその銘柄に合わせる。表示スコアは座標推薦と同じ 45〜100。銘柄名の完全一致は 100
- 意味検索のあと探針は 1 位の点の上へ移る。マップ操作または「地図で選び直す」で座標推薦に戻す
- マップ上の強調は、座標モードでは探針の最近傍、相談モードでは推薦 1 位（探針もそこへ移る）
- No.1 カードは銘柄、産地、象限、相性、理由、粒感・甘み・粘り・旨みを表示
- 詳細パネルは `sommelier_note`、12 指標、季節、酒、気分・場面、`avoid_pairings`、楽天 / Amazon / ふるさと納税 CTA、銘柄ページへのリンクを表示

相談プレースホルダ: `例：刺身に合う、冷めても美味しい、ウイスキーと合わせたい`

## 6. データフロー

```text
初期表示
Browser → Supabase rice_catalog + rice_regions → 味わいマップ（点色は地域マスタ）

座標推薦
Map / sliders → display 座標の距離 → Top 4（ローカル）

意味検索
相談文 → 補助語を内部で足す → embedding
       → RPC match_rice_profiles
       → Flavor Bridge + Gemini の短い返事 → JSON

シード
src/data/rice/*.ts → deriveRiceProfile → buildRiceSearchText
  → createEmbedding → rice_regions / rice_brands / rice_profile_details
```

Supabase を mock data に置き換えない。UI 改修のために未導入の UI / chart 依存を追加しない。

## 7. 状態とアクセシビリティ

- Loading: 正円の静かな pulse と日本語テキスト
- Empty: 銘柄未登録であることと次の行動を表示
- Error: 利用者向け文言と再試行。技術詳細は開発時だけ
- `prefers-reduced-motion` を尊重する
- 味わい評価を公的測定値として表示しない

## 8. 禁止事項

- 教材的な水色方眼・グラフ用紙背景
- 赤い太枠、派手なカプセルの大量使用
- neon、cyberpunk、AI dashboard 表現
- 灰がかったモランディ色（低彩度の苔緑・土紅・梅褐）を地域色や基調に使うこと
- 禁止語: 最強、圧倒的、究極、唯一無二、爆発、神、無敵
- Desktop 右推薦カラムの内部スクロール
- スライダーやマップ操作からの意味検索呼び出し
- 実データを mock data に差し替えること

## 9. 実装上の逸脱（原典からの意図的な差）

原典 `docs/kome-somme-rice-v2-implementation.md` に対し、次の点だけ意図的に異なる。

1. **ランキング座標**: display 座標で順位付けする。Jitter と衝突回避のあとでも、視覚上の最近傍と No.1 を常に一致させるため。
2. **地域色**: 原典の寒色（北海道 `#9fb0c8` など）は使わず、食味図に近い高彩度 7 色にする。
3. **`embedding_model`**: Gemini / OpenAI 両対応のため列と RPC 絞り込みを追加する。
4. **案内役の呼称**: 造語「侍米師」ではなく、日本語として通る **米ソムリエ** を画面に出す。
5. **軸の向き**: 原典は X=粒感・Y=甘み。現行は左すっきり澄む／右甘みふくらむ、下粒立ちしっかり／上やわらか、ほどける。

## 10. 受け入れ基準

- 明るい暖色と、色相の離れた地域色で銘柄の位置がすぐ読める
- マトリクスは左ペインの残り領域いっぱいに広がり、点は米粒、左澄む・右甘み・下粒立ち・上ほどけるが一目で理解できる
- 7 つの地域色は色相が分かれ、同格の銘柄は衝突回避で重ならない
- Desktop は左にマップと現在値、右に No.1・近い銘柄、下に相談が収まり、ページ全体のスクロールがない
- 座標推薦と意味検索が混ざらず、どちらも Top 4 を表示する
- マップの強調は、座標モードでは探針の最近傍、相談モードでは推薦 1 位（探針もそこへ移る）
- `rice_catalog` / 地域色 / embedding 抽象層 / Flavor Bridge / 購買 CTA の V2 データフローが保たれる
