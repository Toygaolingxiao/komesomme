実装はフェーズ単位。この文書を更新してからコードに入る。

世界観は伝わる。初見が迷わず使い、納得して購入に進むにはまだ弱い。今は「雰囲気の良い米推薦デモ」に近く、「購入・比較・選定まで自然に進める実用サービス」には一歩足りない。

### 初見で伝わること

- 米を選ぶサービスである
- 味わいの地図がある
- 今日のおすすめ米が出る
- 料理や気分からも探せる
- 楽天・Amazon・ふるさと納税に進める
- 米ごとに相性料理がある

### 初見で残る疑問

入口が並んでいるのに、役割が整理されていない。

- これは診断？地図で選ぶの？スライダー？相談欄？
- 今日の一膳は最初から出ている。自分は何をすればいい？
- 点は全部米か。色は地域か味か。右のおすすめは地図と連動しているか
- スライダーを動かしたら点が動くのか、おすすめが変わるのか
- 購入ボタンはどれを押せばいいか

現在の入口：地図をクリックする / スライダーを動かす / 言葉で入力する / 今日の一膳を見る / 詳しく見る / 購入する。悪くないが、初見には多い。

## 3. 決定済み方針

1. **購買リンクは 2 列にしない。2 行 × 3 列。**
   - 1 行目・通常購入：楽天市場 / Yahoo!ショッピング / Amazon
   - 2 行目・ふるさと納税：楽天ふるさと納税 / Yahoo!ふるさと納税 / ふるさと納税
   - カテゴリ見出しを付ける。計 6 ボタン
   - スマホもカテゴリごとに 3 列を維持。幅が足りないときだけラベルを短くする。2 列折り返しはしない
2. **上部 CTA は最大 2 つ**（`購入候補を見る` / `ふるさと納税で探す`）。6 ボタンは下部のみ
3. **レーダーは Phase 3。** 主役にしない。詳細の中段に「味わいの輪郭」として置く。名称に「レーダーチャート」は出さない。初期は 6 項目
4. **右カードのバッジ**に「今日の一膳」を重ねない。見出し側で足りる。バッジは相性ラベル + 数値
5. 文言は売り込みではなく「探す」。ボタンは落ち着いた暖色。EC のレジ画面にしない

```
詳細 Hero
  → 上部 CTA（最大 2）
  → 相性・メモ・味わい
  → この銘柄を探す
       通常購入（3 列）
       ふるさと納税（3 列）
```

## 4. 理想導線

今は地図・スライダー・今日の一膳・言葉検索・詳細・購入が並列で混線しやすい。タイプ別に一本化する。

**A 何も分からない人**  
今日の一膳を見る → なぜおすすめか読む → 料理タグ → 詳しく見る → 購入候補

**B 好みがある人**  
粒感・甘みを調整 → 今日の一膳が変わる → 近い銘柄と比較 → 詳しく見る

**C 料理から探したい人**  
言葉で入力 → 料理に合う米を見る → 購入候補

**D 探索したい人**  
地図を触る → 点を比較 → 近い銘柄を見る → 詳細へ

画面上で「どの選び方をするか」が少し見えるようにする。地図が難しい人向けに、言葉検索への短い導線を残す。

### 転換の目安（初見 100 人、感覚値）

| 行動 | 現状予測 | 改善後目標 |
| --- | --- | --- |
| 地図を操作する | 25〜40 | 45〜60 |
| スライダーを動かす | 15〜30 | 30〜45 |
| 詳しく見るを押す | 10〜20 | 25〜40 |
| 言葉検索を試す | 8〜18 | 20〜35 |
| 購入リンクを見る | 5〜12 | 12〜25 |
| 外部購入へ進む | 2〜6 | 5〜12 |

## 6. フェーズ

最短で成果を出す順：Phase 1+2 → 3+4 → 5+6。推薦式・座標・seed・原典は触らない。

### Phase 1 購入導線

目的：購入意欲のある人を逃さない。詳細をスクロールしなくても候補に進める。

対象：`PurchaseLinks.tsx`、`shared.ts` の URL ヘルパー、`src/app/[brand]/page.tsx`、`BrandDetailPanel.tsx`、右カード CTA（`RecommendationRail.tsx` / `MobileCards.tsx`）

タスク

- 詳細上部に軽い CTA を最大 2 つ（購入候補を見る / ふるさと納税で探す）
- 下部はカテゴリ付き **2 行 × 3 列** の 6 リンク。Yahoo!ショッピングと Yahoo!ふるさと納税の検索 URL を追加
- チャネル説明：通常購入は価格や容量を比べたい方に。ふるさと納税は産地を応援しながら返礼品を探したい方に
- 確認注記：購入時は産地・年産・精米時期・内容量をご確認ください
- 右カード CTA を `相性・購入候補を見る`（または `この米の相性を見る`）に。必要なら副次で `購入候補を見る`
- バッジから重複の「今日の一膳」を外す

成功指標：詳細 CTA クリック +30%、購入リンク到達 +50%、外部 EC クリック +20%、詳細離脱 −10%

リスク：ボタン過多、EC 感、品鑑 UI の崩れ。対策は上部 2 つまで、下部で 6 ボタン、文言は「探す」、暖色。

### Phase 2 詳細の情報階層

目的：開いた瞬間に、何が良いか・何に合うか・買う価値があるかが分かること。

対象：`src/app/[brand]/page.tsx`、`BrandDetailPanel.tsx`、必要なら `shared.ts` の派生文

タスク

- Hero に食欲の出る一言（既存 `appetiteLine` 等を活かす。推薦式は変えない）
- 「この米はこんな人に」2〜3 行。既存プロファイルから導出
- 相性料理を上部 CTA の直後〜購入 CTA より前へ
- 主要指標と詳細指標を視覚的に分ける（主要を先、詳細は中段以降）
- 見出し階層と余白を整理。全指標を同じ重みで並べない

成功指標：詳細滞在 +20%、購入 CTA クリック +20%、下部到達 +15%、直帰 −10%

### Phase 3 味わいの輪郭

目的：数値の羅列を減らし、味わいを一目で見せる。

対象：新規チャートコンポーネント、詳細ページ中段

タスク

- 6 項目：甘み / 粒感 / 粘り / 旨み / 香り / 冷めても。欠ける値は既存指標へフォールバック
- SVG 自作を優先（新規 chart ライブラリは足さない）
- 米白地、金茶の線、薄いゴールド／コーラルの面。数値は主張しすぎない
- チャート下に短い要約。スマホは横幅いっぱい、項目名が重ならないこと
- 数値カードは残し、視覚比重だけ下げる。Hero の主役にしない

置く位置：Hero → 上部 CTA → こんな人に → 米ソムリエメモ → **味わいの輪郭** → 詳しい味わい

成功指標：理解度の定性改善、滞在 +10%、購入 CTA +5〜10%、比較クリック +10%

### Phase 4 地図・スライダーの初見理解

目的：地図の使い方、スライダーが変えるもの、右カードとの連動が分かること。

対象：`FlavorMatrix.tsx`、`TasteMap.tsx`、`TasteControls.tsx`、`ProfileNode.tsx`、右欄リスト

タスク

- 説明を行動ベースに。例：点を選ぶと銘柄を表示。スライダーを動かすと、今日の一膳が変わります
- スライダー：数値は小さく、言葉を主役に。動かすと右の「今日の一膳」が変わる旨を短く
- 選択中は強い輝光（既存の産地色を維持）。近い銘柄 02〜04 に細いリング。その他は少し落とす
- リスト hover で地図の点を強調。地図の点 hover で右リスト側も反応。リストクリックで今日の一膳を更新。座標は変えない
- 初回ヒントは小さく 1 つまで。ポップアップ過多は避ける

成功指標：地図クリック +30%、スライダー操作 +25%、右カード更新 +20%、初回離脱 −10%

### Phase 5 比較・回遊

目的：1 銘柄で終わらず、候補を比べて納得して選ぶ。

対象：右欄リスト、詳細の「似ている銘柄」、必要なら対比用の短い派生文（打分は変えない）

タスク

- 近い銘柄に「向いている人 / 日」の一文（軽く食べたい日に、丼もの・定食向き、煮物や肉料理に）
- 詳細に比較ミニカード「似ている銘柄と比べる」
- 「もっと甘みがほしい / もっと粒立ちがほしい / もっと軽く食べたい」は検討。入れるなら座標を直接書き換えず、スライダー誘導に留める

成功指標：似ている銘柄クリック +25%、詳細回遊 +20%、セッション滞在 +15%

### Phase 6 計測

目的：感覚ではなく、どの導線が CV に効くかを見る。

タスク（実装するイベント）

- `map_marker_click` / `slider_change` / `recommendation_detail_click`
- `purchase_cta_click` / `rakuten_click` / `yahoo_click` / `amazon_click` / `furusato_click`
- `language_search_submit` / `suggestion_chip_click` / `similar_rice_click`
- `detail_scroll_50` / `detail_scroll_90`

A/B は設計のみ。このフェーズでは本実装しない。候補：CTA 文言、購入位置、味わいの輪郭の有無、ボタン数（3 vs 6 vs カテゴリ分け）。レイアウト実験でも購買グリッドは 2 列に戻さない。
