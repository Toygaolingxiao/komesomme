# KomeSomme UI デザイン仕様

KomeSomme の UI デザイン正本。実装・レビューは本書を基準にする。

## 1. 体験コンセプト

KomeSomme は、AI ダッシュボードではなく「和紙の味わい地図に触れ、炊きたての一膳を選ぶ」体験である。AI やベクトル検索は裏側に置き、画面では米、産地、料理との相性を主役にする。

- 印象: 明るい、鮮やか、食欲が立つ、上質
- モチーフ: 炊きたての米、果実、旬の食卓。灰がかったモランディ色は使わない
- UI の役割: 味の位置を直感的に選び、推薦の優先順位を迷わず読めること
- 動き: 短い fade、穏やかな spring、探針の淡い ripple。派手な bounce、回転、走査線は使わない

## 2. カラーと質感

基本色は次の4系統とし、白一色や純黒を避ける。灰がかった低彩度（いわゆるモランディ色）は使わない。

- **Rice white**: `#FFFDF7`。マップ面。濁さない
- **Paper**: `#F6EBDD`。ページ地
- **Cream**: `#FFF5E5`。推薦面、タグ
- **Ink**: `#302820`。本文
- **Muted**: `#766658`
- **Brown**: `#704522`
- **Gold**: `#D49A2A`
- **Harvest**: `#E56B3F`。CTA と選択点の強調。銘柄点の塗りには使わない

背景は穏やかな米色。彩りは点・タグ・バッジ・CTA に置く。neon、純黒、寒色の glassmorphism は使わない。Desktop は外枠 1 枚（マップ＋推薦）で画面をまとめ、No.1 だけ内側カードにする。

地域色は旬の食材のように色相を離す。画面は `src/lib/rice/regions.ts` を優先して塗る。

- 北海道・東北: `#7BB8C6`（水）
- 関東・甲信越: `#9BC45E`（若葉）
- 東海・北陸: `#E8B56A`（実り）
- 近畿: `#D4899A`（梅）
- 中国・四国: `#7BB894`（竹）
- 九州・沖縄: `#E8906A`（柿）
- 全国銘柄: `#A892C4`（紫）

銘柄点は炊きたて短粒（産地は薄い blush）。推薦 Top 4 は大きく、あたたかい米色の照り。ほかは減淡。楕円枠は置かない。象限の言葉は軸ラベルに任せ、描画面の中に置かない。

## 3. 味わいマップ

### 軸

軸の向きは左が淡く右が甘い、下がかたく上がやわらか。文言は他サイトの食味図と揃えない。

- X 軸: 左 **すっきり澄む** → 右 **甘みふくらむ**（データは `sweetness` 1〜5）
- Y 軸: 下 **粒立ちしっかり** → 上 **やわらか、ほどける**（データは `hardness`。1=やわらか、5=しっかり。表示 Y だけ反転）
- `stickiness`（粘り）は点サイズと詳細表示に使い、座標軸にはしない

四象限は軸の四隅で読む。描画面の中に象限コピーは置かない。

### 点と探針

- 銘柄点は炊きたて短粒（腹の照りだけ。胚芽の円は描かない）。位置は display 座標のまま
- **推薦 Top 4** は大きく、あたたかい米色の照り（No.1 はやや強く、2〜4 は薄い金）。輪郭の楕円枠は置かない。それ以外は同形のまま色を落とす
- No.1 はテイスティングラベル（県名＋銘柄＋短いタグ）
- No.2〜4 も輝光。ラベルは hover / focus
- その他は淡く残す（消さない）
- **産地凡例は多選**。選んだ地域以外を淡くする（フィルタで消さない）。空なら全点を通常表示。凡例に **解除** で一括クリア。ホバーは一時プレビュー（ピン集合との和）
- preview（モバイル）にも凡例を出す（横スクロール chips）
- 小画面では点を小さくする（キャンバス短辺が約 380px 未満）。**点は間引かない**。同じマスの銘柄数は画面に出さない。点の間隔は重なりを避けるためで、味の差ではない。粒の塗りは産地色を約 4 割混ぜ、凡例は産地色そのもの。地図の強調点は推薦レールと同じ Top 4
- 配置は `calculateMatrixDisplayPoint` の後、決定論的な衝突回避（最小間隔約 0.15 軸単位）
- 探針は墨茶色の小点と淡い波紋。十字照準や HUD にしない

マップクリック、探針ドラッグ、スライダー操作は座標推薦だけを即時更新する。LLM や意味検索を起動しない。

### 動き

味に触れたときだけ、短く動かす。長さはおよそ 160〜280ms。動かすのは transform と opacity。

- 選んだ粒と近い粒は、わずかに大きく、米色の照り。ばねで跳ねさせない。倍率は `transform: scale` でつなぎ、ドラッグ中に飛び跳ねさせない
- それ以外はさらに淡くする（消さない）
- 推薦欄の入れ替えは、同じ枠の中で交叉して淡く切り替える。欄の高さが潰れてページが跳ねない
- セッション初回だけ、粒は探針から外側へ短い stagger で現れる。あとは淡入のみ
- 相談の返事や推薦からの移動では探針がばねで滑る。ドラッグとスライダは 1:1
- モバイルの品鑑は下から上がるシート。ハンドルを下に払うと閉じる
- 編集の挿絵は同じ `view-transition-name` でページをまたいでつなぐ。事典の輪郭は墨線を一度だけ描く
- `prefers-reduced-motion` では拡大も淡入も止める。粒の傾きは残す
- 粒子、蒸気、全画面の視差、相談中のタイプライタ、GSAP / Rive / Lottie は置かない。`/pair` の短い入場はそのまま

マトリクスの描画面は、左ペインの残り領域で軸ラベルと凡例を除いた矩形いっぱいに広げる。銘柄点は枠のすぐ内側（inset 約 4%）まで置く。軸ラベルは描画面の外側の**墨跡ラベル**（serif、重いカプセルにしない）。産地凡例は下。Desktop は 100% 表示で一画面に収める。横軸は左すっきり澄む・右甘みふくらむ。縦軸は下粒立ちしっかり・上やわらか、ほどける。内部の `hardness` は 5=しっかりのまま、表示 Y だけ反転する。

スライダは軸名＋読出し＋両端の**短極点チップ**（枠＋左右キャレットで押せることを示す。例: `‹ 粒立ち` / `ほどける ›`）。別行の説明文は置かない。

相談が返ると探針は **1 位銘柄の表示座標**（jitter 後の点の上）へ移る。地図をドラッグするかスライダーを動かすと座標推薦に戻る。

## 4. 情報設計

### Desktop

```text
┌──────────────────────────────────────┬──────────────────────────┐
│ 味わいの地図                          │ 今日の一膳 No.1            │
│ [ 味わいマップ（残り領域いっぱい） ]    │ 近い銘柄 No.2〜4         │
│ [ 現在の味わい ]                      │ お店で探す ▾              │
└──────────────────────────────────────┴──────────────────────────┘
│ 侍米師に聞く（通欄）                                             │
```

- 左: マップ、その直下に現在の味わい（粒感・甘み）
- 右: No.1（銘柄画があれば 1 枚）→ 近い銘柄 → **折りたたみ**「お店で探す」（展開後は通販 4 / ふるさと 3）。侍米師の返事は置かない
- 相談は両欄の下に通欄。意味検索の返事は相談欄で例句スロットと入れ替える（欄の高さは変えない）。入力欄は残し、続けて聞けるようにする。「地図で選び直す」も相談欄に置く
- Desktop の第一画面（頂栏＋地図面）は `100dvh` に収める。その下に、サイトの説明と料理・特集・銘柄へのリンクを並べた読みもの帯（SSR）を置き、帯までは文書スクロールする。地図面そのものの一画面は変えない
- 左右は同一の外枠に収める。右カラムに**ページ全体**のスクロールを設けない。近い銘柄一覧だけ内側スクロール（バー非表示）可。「お店で探す」は下端固定
- 詳細ダイアログは内容量に応じて独立スクロールしてよい
- 頂栏 `SiteHeader` は Desktop のみ **味わいの地図 → 料理で選ぶ → ライブラリ → ピックアップ**（4 項目、一行）。Mobile は同じ順の下タブ（`/ops` と `/prototypes` では出さない）。副題は常に **侍米師**（読み **じべいし**。ページ名はナビ強調と H1）。版心は `SITE_COLUMN`（`src/components/siteChrome.ts`）。頂栏とフッタはサイト幅の左端。事典・料理詳細・特集・法務の本文は、その中で約 40rem（`READING_COLUMN`）に収めて中央に置く。絵は見出しの下。料理の比較表は本文より広く、同じく中央。
- 法務頁（`/terms` `/privacy` `/tokushoho`）も同じ `SiteHeader`（ナビ現在地なし）。独自の狭い頂栏は置かない
- `html { scrollbar-gutter: stable }` で、スクロールバーの有無による頂栏の横ずれを防ぐ（Desktop Windows）

### 侍米師の道（ホーム）

ホーム `/` は味わいの地図が本体。H1 は「ブランド米の味わいの地図」。初回オーバーレイは置かない。Desktop の頂栏、Mobile の下タブで **料理で選ぶ / ライブラリ / ピックアップ** へ渡す。相談欄の見出しは「侍米師に聞く」。ホームにフッタは置かず、規約・プライバシー・特商法は相談カードの外・下に一行。

| 入口 | 役割 |
| --- | --- |
| 味わいの地図 `/` | 座標を触って今日の一膳 |
| 料理で選ぶ `/pair` | 献立別の比較表（一次データ順） |
| ピックアップ `/discover` | 人手のきょうの三銘柄と特集 |
| ライブラリ `/library` | 銘柄事典の一覧 |

探索用レイアウトは `/prototypes/home`（Curtain / Rail / Ask-first）に残す。本番は常設リンク。

### 銘柄の二層（地図プレビュー / ライブラリ事典）

同じ銘柄の「詳しく」は **一か所** `/library/[id]` に集約する。旧 `/{id}` は永久リダイレクト。

| 層 | 画面 | 役割 | 出すもの |
| --- | --- | --- | --- |
| 選ぶ | ホーム地図・推薦・詳細ダイアログ | 今日の一膳のプレビュー | appetite、料理タグ、主要指標、購入。由来・季節・炊飯は出さない |
| 知る | `/library/[id]` | 統合事典 | 品鑑（味わい・料理・メモ）＋ 由来・季節・酒・炊飯・購入目安 |

ダイアログからの導線は一本:「由来・季節・炊き方まで、ライブラリで読む」→ `/library/[id]`。

### Mobile

1. ヘッダー
2. 今日の一膳 No.1 だけ（提案文は省略せず全文）— 答えを先に出す。No.2〜4 のリストは出さない（地図の強調で足りる）
3. 味わいマップ（**近 1:1** のインライン地図＋スライダ。全画面モードは置かない。凡例 chips・初回ヒントあり）
4. **お店で探す**（折りたたみ。地図の直後。展開後は通販 / ふるさと納税タグ。通販はクリーム地にモール色の細い帯）
5. 侍米師に聞く相談（第二条路径。例句は折り返し、返答は高さ可変）
6. 規約ナビと「きょうの読みもの」（相談カードの外。ページ下端）
7. ページ下端は十分な余白と `safe-area-inset-bottom` で、例句がブラウザ底に食い込まないようにする

Mobile は文書スクロール可。Desktop の `100dvh` ロックは第一画面だけ（`lg` 以上）。読みもの帯は両方ともスクロールして読む。地図は今日の一膳の**直下**。購入は地図の直後・相談の前（折りたたみ維持）。規約リンクは相談カードに入れない。

購入リンク（ホーム）: 既定は次級 CTA のみ。展開後は **通販 / ふるさと納税** のタグ切替。通販は楽天 → Yahoo → Amazon → メルカリ（検索アフィ）。ふるさとは楽天（アフィ）→ Yahoo（プレーン検索）→ さとふる。ホーム compact は **2×2**（右欄で 4 段が切れないため）。ライブラリの `full` は縦一列。ボタンはクリーム地・墨字・左に 4px のモール色。塗りは内側 span（`:visited` で背景が消えない）。品鑑ダイアログはモール列を出さず、事典の購入欄へ飛ぶ。

## 5. 推薦表示

- **座標推薦**: クライアントで display 座標の距離を計算し、Top 4 を即時表示。距離スコアは並び用で、画面には出さない
- **意味検索**: 相談フォーム送信時だけ `POST /api/rice/semantic-recommend` を呼ぶ。銘柄名の完全一致が先。相談文が料理ページの別名を含むときは、そのページの Top 4 を embedding の前に返し、「比較表で見る」を出す（Gemini は呼ばない）。それ以外は相談文に食味の補助語を足してから embedding し、Top 4 を取ったあと Gemini が返事を書く。銘柄名の創作はしない。返事は相談欄に出し、入力欄は残す。探針は 1 位の表示座標へ移し、マップの強調もその銘柄に合わせる。スコア数字は出さない。例句チップは押した時点でその文を送る
- 意味検索のあと探針は 1 位の点の上へ移る。マップ操作または「地図で選び直す」で座標推薦に戻す
- マップ上の強調は、座標モードでは探針の最近傍（Top 4）、相談モードでは推薦 1 位（探針もそこへ移る）。スライダーまたは探針を動かすと開いている詳細は閉じ、点した粒の強調は残さない。Desktop は粒をクリックすると品鑑を開く。Mobile は最初のタップで探針と Top 4 だけ動かし、同じ粒をもう一度タップすると品鑑を開く。Mobile の配置は一膳が上、地図はインライン
- No.1 カードは銘柄、産地、理由、料理タグを表示。相性スコア数字は置かない
- 詳細パネル（銘柄品鑑）は重点説明に絞る: `sommelier_note`、主要指標、料理・食材・`avoid_pairings`、気分・場面。深掘りはライブラリ一本
- 購入 CTA は **Sommelier-first / Progressive Disclosure**: ホームは「お店で探す」を折りたたみ。展開後は **通販 / ふるさと納税** タグ。通販は楽天 → Yahoo → Amazon → メルカリ（検索アフィ）。クリーム地にモール色の細い帯
- **モール帯は 1 ページ 1 箇所**。ホームの品鑑は事典の購入欄へのリンクのみ。ライブラリ事典は「購入の目安」に本体、見出し付近は下部へのジャンプのみ（上下二重のモール列は置かない）
- 購入 UI 全体のゲート: `NEXT_PUBLIC_SHOP_LINKS_ENABLED` / `SHOP_LINKS_ENABLED`（`0` で非表示。未設定は表示）
- Amazon 定型文は **フッター一箇所**（ホームは 100dvh のためフッターなし、CTA は ※PR のみ）。表面は [15-disclosure-surfaces.md](./15-disclosure-surfaces.md)
- `/library/[id]` が銘柄の正本ページ。ヘッダー・地図・ライブラリ本文は共通の `SITE_COLUMN`（`max-w-[1440px]` + 左右 padding）。ナビ順は常に **味わいの地図 → 料理で選ぶ → ライブラリ → ピックアップ**、現在地は `font-semibold` + ink で強調。旧 `/{id}` は `/library/[id]` へ永久リダイレクト
- ホーム詳細パネルは浅路由を書かない。地図の操作は history に残さない。共有リンク `/?brand=<id>` は初回ロードだけ読む。深読みは `/library/[id]`

### ライブラリの発見（検索以外）

正本は [19-editorial-discovery.md](./19-editorial-discovery.md)。ホーム地図の座標推薦とは別系統。Desktop `100dvh` の地図面には特集もイラスト帯も置かない。特集へのリンクは第一画面の下の読みもの帯に置く。

- **ピックアップ** `/discover`：きょうの三銘柄 + 料理で選ぶ（献立の 5:4 サムネ格子）+ 特集一覧（`#collections`）。ナビは一級ここだけ。特集はモバイルもサムネ＋見出し（通欄の大きな正方形は置かない）
- **特集誌面** `/collections/[slug]`：人手編集。索引 `/collections` は `/discover` へリダイレクト。旧 `/library/collections/*` も誌面へ
- `/library` は編集マストヘッド → 品評表のみ
- 一覧の味わい表示は数字壁より **金の pips**（`TastePips`）を優先。長文 headline は事典側

銘柄ビジュアルは [18-brand-illustration.md](./18-brand-illustration.md)。本番ファイルは `public/brand-art/`。

相談プレースホルダ: `例：刺身に合う、冷めても美味しい、ウイスキーと合わせたい`

## 6. データフロー

```text
初期表示
Browser → Supabase rice_catalog + rice_regions → 味わいマップ（点色は地域マスタ）

座標推薦
Map / sliders → display 座標の距離 → Top 4（ローカル）

意味検索
相談文 → 補助語を内部で足す → embedding
       → RPC match_rice_profiles
       → Flavor Bridge + Gemini の短い返事 → JSON

シード
src/data/rice/*.ts → deriveRiceProfile → buildRiceSearchText
  → createEmbedding → rice_regions / rice_brands / rice_profile_details
```

Supabase を mock data に置き換えない。UI 改修のために未導入の UI / chart 依存を追加しない。

## 7. 状態とアクセシビリティ

- Loading: 正円の静かな pulse と日本語テキスト
- Empty: 銘柄未登録であることと次の行動を表示
- Error: 利用者向け文言と再試行。技術詳細は開発時だけ
- `prefers-reduced-motion` を尊重する（地図の粒と推薦欄は §3「動き」）
- 味わい評価を公的測定値として表示しない

## 8. 禁止事項

- 教材的な水色方眼・グラフ用紙背景
- 赤い太枠、派手なカプセルの大量使用
- neon、cyberpunk、AI dashboard 表現
- 灰がかったモランディ色（低彩度の苔緑・土紅・梅褐）を地域色や基調に使うこと
- 禁止語: 最強、圧倒的、究極、唯一無二、爆発、神、無敵
- Desktop 右推薦カラムの**ページ全体**スクロール（一覧の内側スクロールは可）
- スライダーやマップ操作からの意味検索呼び出し
- 実データを mock data に差し替えること
- 頂栏の副題をページごとに変えること（ページ名はナビと H1 に置く）

## 9. 設計上の決定事項

初期案から現行に至るまで、意図的に固定している点。

1. **ランキング座標**: display 座標で順位付け。Jitter 後も視覚上の最近傍と No.1 を一致させる。
2. **地域色**: マスタ 7 色は凡例・タグ用（淡めの食欲色）。地図の銘柄点は米色基調＋薄い産地 blush（`mapGrainFill`。表示は常に `regions.ts` 正本）。
3. **`embedding_model`**: Gemini / OpenAI 両対応。RPC でモデルを絞る。
4. **案内役**: 画面表記は **侍米師**（指定読み **じべいし**）。「米ソムリエ／コメソムリエ」は使わない。
5. **軸**: 左すっきり澄む／右甘みふくらむ、下粒立ちしっかり／上やわらか、ほどける（`sweetness` / `hardness`）。

## 10. 内部観測台 `/ops`（非公開）

公開面の和紙トーンとは切り離す。暗いアトリエ、運用者向けラベル（中国語）。`SiteHeader`・購入 CTA・アフィ文言を出さない。recharts は `/ops` に限定し、味わい地図へ持ち込まない。Yahoo 公式短鎖の記入表は `/ops/yahoo`（通販）。`/ops/yahoo-furusato` は残すが、寄附が成果対象外のため公開ボタンは使わない。

## 11. 受け入れ基準

- 明るい暖色と、色相の離れた地域色で銘柄の位置がすぐ読める
- マトリクスは左ペインの残り領域いっぱいに広がり、点は米粒、左澄む・右甘み・下粒立ち・上ほどけるが一目で理解できる
- 7 つの地域色は色相が分かれ、同格の銘柄は衝突回避で重ならない
- Desktop は左にマップと現在値、右に No.1・近い銘柄、下に相談が第一画面に収まる。その下の読みもの帯までスクロールできる
- 座標推薦と意味検索が混ざらず、どちらも Top 4 を表示する
- マップの強調は、座標モードでは探針の最近傍、相談モードでは推薦 1 位（探針もそこへ移る）
- `rice_catalog` / 地域色 / embedding 抽象層 / Flavor Bridge / 購買 CTA の V2 データフローが保たれる
