# KomeSomme 历程回顾（构想 → 现行）

本文用中文记录：从零构想，到仓库根目录 [`VERSION`](../VERSION) 所标版本为止。日语版是 [12-product-journey.ja.md](./12-product-journey.ja.md)。技术栈与 RAG 细节见日文 [02-tech-retrospective.md](./02-tech-retrospective.md)。未完成的上线任务见 [11-launch-checklist.md](./11-launch-checklist.md)。

读者：产品主理人 GAO，以及之后接手的开发者 / 顾问。

---

## 1. 一句话

KomeSomme 不是「米的数据库网站」，也不是「用 LLM 聊天荐米」。它是一张可触摸的和纸味觉地图：手用来选位置，嘴用来咨询米ソムリエ，钱走搜索型购买链接。向量检索和短回复藏在后面。

## 3. 咨询师视角

### 3.1 机会为什么成立

日本品牌米的比较成本很高：店头是名字和产地，食味图各站轴不一样，ふるさと纳税和电商又是另一套搜索词。KomeSomme 把「我今晚吃什么」收成一个手势（地图）加一句话（咨询），购买只做到「带着关键词离开」，不自建库存。这和「做一个更全的米 wiki」不是同一场战争。

可变现切口从一开始就清楚：乐天 / Yahoo / Amazon / ふるさと的 **搜索 CTA + アフィタグ**，而不是先做商品 API。API 是 P2；标签才是 1.0 前该接线的。

### 3.2 定位上刻意不做的

- 不当营养 / 公定食味计：分数是编辑评价，UI 和隐私文案都要守住这条，否则一次「测谎」会毁掉信任。
- 不当全能 AI：推荐排序不交给 LLM。LLM 只在 Top 4 确定之后写两句，且不准发明名单外的铭柄。
- 不当角色 IP：不用侍、刀、卡通代言。探针和米粒是符号，米ソムリエ是职能名。
- 不在营销里用 最強 / 圧倒的 / 究極 / 唯一無二 / 爆発 / 神 / 無敵。连「神奈川」都曾误触「神」——说明禁词要配白名单，不能只靠子串。

### 3.3 商业与合规上仍裸着的部分

体验已经能给朋友看；**作为带アフィ的正式站还差几块钱和几张纸**：

- 特商法事業者栏仍是占位（日本公开销售的硬门槛）
- アフィタグ未接，点击进得了店，成果回不来账
- GTM ID 未配，GA4 没有第一周 CVR
- 没有 Sentry，咨询 502 只能翻 Vercel 日志

顾问式的建议：1.0.0 不要等 Auth、收藏、煮饭建议。等 **特商法填实 + 至少一个アフィ渠道能对账 + 烟雾测试留档**。观测可以先靠 `access_events`，GTM 是加分不是挡路。

### 3.4 产品风险（现在就能说的）

| 风险 | 含义 |
| --- | --- |
| 分数争议 | 外部图的轴和我们的甘み×粒立ち不同。再校正用了「图共识 × 公开资料 × 旧值、冲突从保守」，但用户仍可能拿着别的图来对质。应对是透明：编辑分、轴定义写在画面上。 |
| 咨询幻觉 | 已用 Flavor Bridge + 短回复约束压住。不要为了「更聪明」把整本 catalog 塞进 prompt。 |
| 成本 | 地图免费；咨询按次 embedding + 可选 LLM。限流和 kill switch 必须留着。 |
| 目录不全 | 图上有、catalog 没有的铭柄（秋の詩 等）有意没加。缺货感知会伤害「专家感」，加铭柄要走同一套 derive / validate / seed，不要手塞 DB。 |

## 4. 开发者视角

### 4.1 选对了的架构

**双轨推荐**是整站最值钱的决定。坐标操作走客户端，咨询才碰 Gemini / pgvector。体感快、账单可控、故障时地图仍能用。

**打分在 Git、检索在 DB。** `validate:rice` 在 seed 之前挡住重复 ID、禁词、必填数组。改味道是改 `sources/`（或 `scripts/data/` 正本再 apply），不是在 Table Editor 里拧数字。

**RAG 只做到检索 + 规则说明。** Corpus 是自然日语 `search_text`，不是 JSON 键名；Index 是 pgvector；Generator 极轻。这比「聊天机器人套一层米」容易测、容易回滚。

**匿名面尽量小。** 0004 之后 embedding / RPC 对 anon 不可见；`access_events` 只能由 service role 写入。浏览器只拿 catalog 行。

### 4.2 踩过的坑

- **网络：** Gemini / Supabase 的 `fetch failed` 会在灌库开头连续失败。embedding 有重试不够，upsert 也要重试。企业 CA 用 `--use-system-ca`。
- **轴映射：** 外部图是 もちもち / あっさり 等，我们的轴不改名、只映射。改轴等于改产品记忆，必须主理人点头。
- **文档里的「当前版本号」：** 曾经写进 overview、checklist、changelog 文首、docs 索引。漏一处就像文档在撒谎。正本现已收成 `VERSION` + `package.json`。
- **空壳模块：** 未接线的 `RakutenAffiliateClient`、未使用的 `createServerClient`、示例里的アフィ env，会让人以为已经接上。没有读代码的 env 不要出现在 `.env.example`。
- **密钥：** 整理 `.env.local` 等于让代理读到 service_role。以后只改 `.env.example`，本地文件人对齐。

### 4.3 和代理一起开发时真正有效的约束

写进 Cursor rule / 文档、并且被反复执行过的：

- 不改推荐公式和坐标公式（除非明确要求）
- 不 mock、不擅自 seed 生产
- UI 日文、对 GAO 说明用中文
- 升号与用户可感知的 `main` 提交同一批；1.0.0 禁止夹带

没有这些，代理会「顺便」改打分、改文案口吻、每个 commit 都 bump、或者把 service_role 写进 `NEXT_PUBLIC_`。

### 4.4 代码与文档怎么分工（现行）

| 想做的事 | 打开 |
| --- | --- |
| 改画面 | `08` → `src/components` |
| 改打分 / 短文案 | `src/data/rice/sources/`，再 `validate:rice` / `seed:rice` |
| 再校正依据 | `scripts/data/` |
| 改检索 / 回复 | `05`、`src/lib/rice/`、semantic route |
| 上线还差什么 | `11` |

| 版本号 | 只动 `VERSION`、`package.json`、`10-changelog.md` |

`07-roadmap.md` 是 UX 阶段的**完成记录**，不是现在的 backlog。

## 5. 课题（还压在桌上的）

按对「能公开收アフィ」的阻挡程度：

1. 特商法填写  
2. 至少一个アフィ渠道的标签 + 对账方法  
3. 烟雾测试按 `smoke-test.md` 留档  
4. `NEXT_PUBLIC_GTM_ID`（可选但便宜）  
5. Sentry（咨询失败率）  
6. 独自ドメイン  

不要在这之前展开 Auth、收藏、煮饭建议、商品搜索 API。那是另一条产品曲线。

## 6. 收获（建议下次项目直接带走）

1. **先规定「什么绝对不改」。** 这里是公式、轴、案内役名称。其余才可以迭代。
2. **用户手势和计费动作分开。** 拖地图免费；按咨询才调用模型。
3. **正本越少越好。** 版本号两处、env 一处模板、打分一套 sources。第三份「当前状态」一定会过期。
4. **编辑型数据要可审计。** 再校正留下 extract / overrides / reason，比「我记得挪过」有用。
5. **上线检查表按 Done 条件写，不按愿望写。** `11` 的 P0/P1 比「将来要件」清单更可执行；`06` 的将来节已改为指向 `11`。
6. **代理是加速器，不是密钥保管柜。** 模板可以代劳，`.env.local` 不要打开。
